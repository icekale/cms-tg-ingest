# 审计稳定性修复设计

## 背景

`v0.2.48` 的全量代码审计确认了若干未被现有测试覆盖的故障窗口，主要集中在 115 残留清理、请求节流、任务 claim、STRM 替换、Web 协议适配、HDHive 去重、备份与质量巡检。此次只修复已经能够从当前代码路径证明的问题，不调整正常工作流和用户配置语义。

## 目标

- 115 文件只有在能够证明属于当前任务时才允许自动删除。
- 每一次 115 物理请求都经过同一节流逻辑并计入调用统计；429 尊重服务端冷却时间。
- 没有 TMDB、标题或任务时间边界证据时，不再用“唯一候选”推断任务身份。
- TaskRunner 在结果持久化失败后快速释放或继续维护 claim，避免六小时停滞。
- STRM 替换、115 云下载和 CMS 自动整理具备可恢复的提交边界。
- Web 的真实 HTTP 行为与 API 测试一致，所有 API 输出统一递归脱敏。
- HDHive 在 Emby 不可用时不自动消费积分，空结果与查询失败分开处理。
- 备份和质量巡检能够隔离局部故障并继续下一次调度。

## 设计

### 115 安全边界

残留清理要求候选具有不早于任务创建时间的有限正数远端时间戳，并优先要求 TMDB 精确匹配；没有 TMDB 时只允许标准化完整标题匹配，且候选年份与任务年份冲突时直接拒绝。缺少时间戳或只有子串命中的候选一律保留。HTTP 通用层不再对 115 请求进行不可观测的内部重试；`P115WebClient` 将 429 转成可观测的风控错误，`TaskRunner` 使用配置冷却时间与数字或 HTTP 日期格式 `Retry-After` 中的较大值统一退避。

### 身份与任务恢复

最近直链目录优先按 TMDB 精确匹配或唯一标题 token 匹配；只有候选唯一且其目录与 STRM 均落在有效的正数任务时间边界之后时，才允许无身份命中的崩溃恢复兜底。没有任务时间证据的唯一候选必须拒绝。TaskRunner 保持 active claim 和心跳续租直至结果持久化完成；领取任务后的任一未处理异常都会立即释放自己的 claim，释放失败则在领取下一任务前继续清理，避免等待六小时过期。

### 副作用与文件提交

STRM 冲突合并先记录 `moving`，再把每个新 STRM 写到临时文件并通过 `os.replace` 覆盖旧文件，不预先删除目标；只有目标分享标记和文件内容均与源文件一致时才允许跳过覆盖。云下载与 CMS 自动整理复用 TaskStore operation journal：先持久化 intent，再执行远端操作，重放时先恢复远端状态或复用已开始操作。CMS 自动整理无法区分“调用前崩溃”和“调用后落盘失败”，因此不确定状态进入人工处理，禁止重复触发或假报成功；其有副作用的 GET 使用单次物理尝试，避免通用安全 GET 重试重复触发。

### Web 与脱敏

真实服务器补充 `DELETE` Handler。任务、事件、HDHive 错误和后台作业统一经过递归结构脱敏；字符串使用同一个凭据脱敏器，结构化键和 URL 查询键同时识别 `*_token`、`*_api_key`、`*_cookie` 和密码类后缀，自有分享访问码摘要只输出固定公开字段。SSE 在注册前后和循环中监听服务器停止事件，关闭时拒绝新订阅并唤醒、注销已有订阅。

### HDHive、备份与巡检

Emby 查询返回空集合表示查询成功但没有已有剧集；只有异常才表示不可用。自动解锁在 Emby 不可用时 fail closed。备份只有完全成功或明确全部跳过时才记录当天完成；`partial` 结果允许当天重试，但自动循环至少退避一小时，异常状态写入本身也被隔离。质量巡检按文件隔离读取错误，并缓存同一目标目录的 STRM 内容，避免追更任务重复全量读取。

## 非目标

- 不增加 HDHive 单次运行总积分上限；当前 `HDHIVE_AUTO_UNLOCK_MAX_POINTS` 仍是单资源阈值。
- 不改变 WEB_TOKEN 留空时的局域网免鉴权语义。
- 不重构现有大文件或迁移数据库。

## 验收

- 每个已确认问题都有先失败后通过的回归测试。
- Python、前端测试和前端构建全部通过。
- `python3 -m compileall -q app bridge.py doctor.py` 通过。
- 工作流正常成功路径的调用次数、阶段顺序和用户提示不回归。
