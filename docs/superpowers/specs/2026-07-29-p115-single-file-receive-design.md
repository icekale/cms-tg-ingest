# 115 单文件接收项识别修复设计

## 背景

115 的目录列表对普通文件返回 `fid=文件 ID`、`cid=父目录 ID`，对文件夹则使用 `cid=文件夹 ID`、`pid=父目录 ID`。当前接收恢复代码统一调用 `p115_file_id()`；该函数优先返回 `cid`，导致普通文件被误认成接收目录本身并被过滤。文件夹分享可以完成，单个 MKV 等普通文件会一直缺少 `received_items`。

## 目标

- 正确识别真实 115 `{fid, cid}` 普通文件记录的文件 ID 和父目录 ID。
- 保持文件夹接收、同名排除、并发接收防串任务和接收快照语义不变。
- 不改变任务数据库，不重试生产任务，也不增加 115 或 CMS 调用。

## 方案比较

1. 在接收项规范化调用点使用现有 `p115_item_id()` 和 `p115_item_parent_id()`（采用）。改动范围最小，同时明确支持文件与文件夹两种记录结构。
2. 修改全局 `p115_file_id()` 的优先级。会影响搜索、整理、清理等大量既有调用，回归范围过大。
3. 在接收函数内直接写 `fid/cid/pid` 条件分支。行为可行，但会重复已有帮助函数并增加后续语义漂移风险。

## 设计

`P115WebClient._normalized_received_item()` 只负责把一个真实 115 列表条目转为统一接收项：

- 使用 `p115_item_id()` 取得普通文件的 `fid` 或文件夹的 `cid`。
- 使用 `p115_item_parent_id()` 取得普通文件的 `cid` 或文件夹的 `pid`。
- 保留现有目标目录校验、名称校验、更新时间和 `received_item_verified` 行为。
- 不修改 `p115_file_id()`，避免影响不属于本缺陷的调用方。

接收前快照同样必须记录条目的真实 ID，否则同名旧文件不能被排除。因此 `_prepare_share_receive()` 的 `target_pre_call_file_ids` 也使用 `p115_item_id()`。

历史任务可能已经保存了不完整的 `received_items`，整理阶段会通过 `_recover_received_items_for_hint()` 再次读取待整理目录。该恢复函数也必须使用 `p115_item_id()` 和 `p115_item_parent_id()`，否则修复只能保护新任务，不能正确处理仍留在待整理目录中的历史普通文件。恢复范围仍限定为完整接收前快照之外、TMDB 标记精确匹配且数量符合预期的条目。旧版本可能已把接收目录 CID 当成普通文件 ID 写入快照；当 `received_existing_file_ids` 包含接收目录 CID 时，基线无法安全区分旧文件和新文件，恢复必须直接返回空结果并继续 fail-closed 等待人工处理。

## 测试

在 `tests/test_http_clients.py` 和独立的 `tests/test_p115_single_file_receive.py` 增加真实普通文件载荷：列表条目同时包含 `fid` 和 `cid`，且不包含人工构造的 `pid`。测试覆盖：

- 接收前快照保存旧文件的 `fid`，而不是父目录 `cid`。
- 接收后能够选中新文件的 `fid`，父目录保持目标 `cid`。
- 旧同名文件仍被排除，结果完整且已验证。
- 历史 TMDB 提示恢复只返回不在旧快照中的新普通文件，并保留真实 `fid/cid`。
- 包含接收目录 CID 的旧格式快照禁止自动恢复，避免误选同名旧文件。
- 现有文件夹接收测试保持通过。
