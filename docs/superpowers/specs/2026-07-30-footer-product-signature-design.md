# 页脚产品签名栏设计

## 背景

当前 Vue 管理界面的页脚只居中显示 `cms-tg-ingest` 和版本号，视觉上像一段调试文本，和顶部已有的媒体仓品牌不一致。用户希望页脚更专业，但不需要增加复杂功能。

## 目标

- 将页脚改为与顶部品牌一致的产品签名栏。
- 清晰展示品牌名称、副标题和当前版本。
- 保持页脚轻量，不重复概览页已有的运行状态。
- 兼容桌面端和窄屏，不改变现有页面主体与后端接口。

## 非目标

- 不增加新的 API 或设置项。
- 不在页脚显示健康状态、版权信息、链接或诊断数据。
- 不重构整体布局，不修改旧 Web UI 或业务工作流。

## 设计

页脚位于主内容列底部，使用白色背景和一条浅色顶部边界与内容区分开。左侧为 24px 品牌 Logo、产品名“入库助手”和副标题“115 · CMS · Emby 工作流”；右侧为低饱和蓝色圆角版本标签，例如 `v0.2.52`。

版本继续来自现有 `settings` API。API 请求失败时保留 Logo、产品名和副标题，只隐藏版本标签，保证页脚仍然完整可识别。

桌面端保留左右布局，水平内边距与内容区一致；窄屏时隐藏副标题，保留 Logo、产品名和版本标签，避免内容挤压或换行。页脚文字使用现有字体和颜色系统，不引入新的字体或依赖。

## 实现范围

- 修改 `frontend/src/App.vue` 的页脚模板，复用现有 `brandLogoUrl` 和 `program.version`。
- 修改 `frontend/src/styles.css`，增加页脚签名、版本标签和移动端规则。
- 扩展 `tests/test_frontend.py`，验证品牌 Logo、副标题、版本标签和响应式样式契约。

## 验收标准

1. 桌面端页脚显示 Logo、“入库助手”、“115 · CMS · Emby 工作流”和版本标签。
2. 版本标签只在版本数据存在时显示，API 失败时不会出现空标签。
3. 窄屏页脚不出现横向溢出，副标题隐藏但品牌和版本仍可辨认。
4. 既有前端测试、Node 生产构建和 Python 测试保持通过。
5. 视觉检查确认页脚与顶部品牌、现有浅色后台风格保持一致。
